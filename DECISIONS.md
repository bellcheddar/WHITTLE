# WHITTLE decisions

One line per decision: what was decided, the alternative, the reason, and how to reverse it.
Decisions 1-8 of Appendix B are pre-taken and are not relitigated here.

| # | Decision | Alternative | Reason | Reverse by |
|---|---|---|---|---|
| 9 | Hardware is an M2 Ultra Studio, not the M1 Ultra the spec assumes. float32 kept everywhere anyway, bf16 never enabled. | Enable bf16 on M2, which does have hardware support | Spec 2.2 and CLAUDE.md are authoritative, and one numeric regime across the whole run keeps the Tm model and the Tier 2 co-folds comparable to any rerun on an M1 box. The gain from bf16 on a ~125 aa fold is small. | Set `precision = "bfloat16"` in `config/hardware.toml` and retrain the Tm model |
| 10 | Two pixi environments: `default` (python 3.12, Tier 0/1) and `cofold` (python 3.11, boltz-community, `no-default-feature`). | One environment for everything | boltz pins numpy<2 and has no cp312 wheel for it, the ceiling BoltzMaker documents. A single environment makes a Tier 2 install able to break Tier 1. | Merge the features in `pixi.toml` once boltz-community ships a cp312 numpy-2 build |
| 11 | Droplet port 8021. | Any port above 8015 | Probed with `ss -ltn`: 8000-8015, 8041 and 8090 are in use; 8021 is the lowest free port at or above the floor spec 4.5 sets. | Change `bind_addr` in `config/deploy.toml` and in `deploy/nginx.whittle.conf`, then re-provision |
| 12 | ANARCI from bioconda (noarch, prebuilt IMGT HMMs), not from GitHub source. | `anarcii` (the documented fallback) | The source build shells out to a bundled `muscle_macOS` that is not in the sdist, and muscle 5 does not take muscle 3's flags, so the wheel cannot build on macOS. ImmuneBuilder imports `anarci` unconditionally, so the fallback would also have cost the NanoBodyBuilder2 axis. All 2,500 sequences numbered by ANARCI: no row used the fallback. | Drop `anarci` from `pixi.toml` and let `number_many` fall through to `anarcii` |
| 13 | Hallmark reported as a graded 0-4 count plus a strict all-four boolean, reconciled against the upstream column under both rules. | Report only the strict boolean and declare the 92.8 percent agreement a control failure | The upstream `hallmark` column implements "at least three of four tetrad positions camelid" (99.3 percent agreement), not "all four" (92.8 percent). The strict call is the honest one and the graded count is the informative one, so the app shows both and the About tab states the rule difference. This is a finding about the upstream column, which spec 5.1 told us not to trust, and it inverts no ranking, so it is not blocker B3. | Treat `hallmark_n >= 3` as intact in `pipeline/tier0.py` |
| 14 | CDR3 clustering kept on MMseqs2, with a greedy CD-HIT-equivalent route as the automatic fallback when MMseqs2 answers degenerately. | Greedy only, since CDR3s are 8-25 aa and MMseqs2 is built for longer sequences | Both routes were run on GLP1R and returned the same 495 clusters, and a brute-force pairwise check over 200 CDR3s found a single pair at or above 90 percent identity. The CDR3s are genuinely almost all unique, so the two routes agree and the spec's named tool stands. | Set `cluster_mmseqs` to return None unconditionally |
| 15 | The explorer distinguishes Pareto-front from dominated candidates by colour, lightness and opacity, not by line weight. | Replace Plotly parcoords with a hand-written SVG parallel-coordinates plot that can vary stroke width | DESIGN 3.1 asks for both colour and line weight, but plotly.js parcoords has no per-line width attribute: verified against `Plotly.PlotSchema.get().traces.parcoords.attributes.line`, which carries colour attributes only, and the lines are drawn to a WebGL canvas so CSS cannot reach them. Spec 8.1 mandates parcoords and a custom partial bundle built around it. The substitute channel is a large lightness step (#C3CBD9 at 0.5 opacity under #3457A6 at 0.92), which is what survives greyscale and colour-vision deficiency; the legend swatches carry the weight difference, and the Pareto toggle shows the front alone. | Write an SVG parallel-coordinates component and drop parcoords from the Plotly bundle |
