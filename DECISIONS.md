# WHITTLE decisions

One line per decision: what was decided, the alternative, the reason, and how to reverse it.
Decisions 1-8 of Appendix B are pre-taken and are not relitigated here.

| # | Decision | Alternative | Reason | Reverse by |
|---|---|---|---|---|
| 9 | Hardware is an M2 Ultra Studio, not the M1 Ultra the spec assumes. float32 kept everywhere anyway, bf16 never enabled. | Enable bf16 on M2, which does have hardware support | Spec 2.2 and CLAUDE.md are authoritative, and one numeric regime across the whole run keeps the Tm model and the Tier 2 co-folds comparable to any rerun on an M1 box. The gain from bf16 on a ~125 aa fold is small. | Set `precision = "bfloat16"` in `config/hardware.toml` and retrain the Tm model |
| 10 | Two pixi environments: `default` (python 3.12, Tier 0/1) and `cofold` (python 3.11, boltz-community, `no-default-feature`). | One environment for everything | boltz pins numpy<2 and has no cp312 wheel for it, the ceiling BoltzMaker documents. A single environment makes a Tier 2 install able to break Tier 1. | Merge the features in `pixi.toml` once boltz-community ships a cp312 numpy-2 build |
| 11 | Droplet port 8021. | Any port above 8015 | Probed with `ss -ltn`: 8000-8015, 8041 and 8090 are in use; 8021 is the lowest free port at or above the floor spec 4.5 sets. | Change `bind_addr` in `config/deploy.toml` and in `deploy/nginx.whittle.conf`, then re-provision |
| 12 | ANARCI from bioconda (noarch, prebuilt IMGT HMMs), not from GitHub source. | `anarcii` (the documented fallback) | The source build shells out to a bundled `muscle_macOS` that is not in the sdist, and muscle 5 does not take muscle 3's flags, so the wheel cannot build on macOS. ImmuneBuilder imports `anarci` unconditionally, so the fallback would also have cost the NanoBodyBuilder2 axis. All 2,500 sequences numbered by ANARCI: no row used the fallback. | Drop `anarci` from `pixi.toml` and let `number_many` fall through to `anarcii` |
| 13 | Hallmark reported as a graded 0-4 count plus a strict all-four boolean, reconciled against the upstream column under both rules. | Report only the strict boolean and declare the 92.8 percent agreement a control failure | The upstream `hallmark` column implements "at least three of four tetrad positions camelid" (99.3 percent agreement), not "all four" (92.8 percent). The strict call is the honest one and the graded count is the informative one, so the app shows both and the About tab states the rule difference. This is a finding about the upstream column, which spec 5.1 told us not to trust, and it inverts no ranking, so it is not blocker B3. | Treat `hallmark_n >= 3` as intact in `pipeline/tier0.py` |
| 14 | CDR3 clustering kept on MMseqs2, with a greedy CD-HIT-equivalent route as the automatic fallback when MMseqs2 answers degenerately. | Greedy only, since CDR3s are 8-25 aa and MMseqs2 is built for longer sequences | Both routes were run on GLP1R and returned the same 495 clusters, and a brute-force pairwise check over 200 CDR3s found a single pair at or above 90 percent identity. The CDR3s are genuinely almost all unique, so the two routes agree and the spec's named tool stands. | Set `cluster_mmseqs` to return None unconditionally |
| 15 | The explorer distinguishes Pareto-front from dominated candidates by colour, lightness and opacity, not by line weight. | Replace Plotly parcoords with a hand-written SVG parallel-coordinates plot that can vary stroke width | DESIGN 3.1 asks for both colour and line weight, but plotly.js parcoords has no per-line width attribute: verified against `Plotly.PlotSchema.get().traces.parcoords.attributes.line`, which carries colour attributes only, and the lines are drawn to a WebGL canvas so CSS cannot reach them. Spec 8.1 mandates parcoords and a custom partial bundle built around it. The substitute channel is a large lightness step (#C3CBD9 at 0.5 opacity under #3457A6 at 0.92), which is what survives greyscale and colour-vision deficiency; the legend swatches carry the weight difference, and the Pareto toggle shows the front alone. | Write an SVG parallel-coordinates component and drop parcoords from the Plotly bundle |
| 16 | Surface patches use a continuous Spatial-Aggregation-Propensity-style neighbourhood sum at 7.5 angstroms, not a hard "cluster of at least three residues" rule. | Keep the cluster rule and report zero where no cluster forms | The cluster rule was implemented first and returns zero for almost every VHH model: at 125 residues the exposed same-class residues form singletons and pairs, so the column reported a threshold artefact rather than a measurement. The neighbourhood sum is continuous, cannot degenerate, and follows Chennamsetty et al. (2009) PNAS 106:11937. The cluster count is kept beside it as a shape descriptor. | Report `*_patch_count` as the headline figure in `pipeline/patches.py` |
| 17 | Protein-Sol reimplemented from the authors' published reference statistics and algorithm statement, and validated against their own worked example. | Drop the Protein-Sol term and ship SWI alone | The 2017 paper does not publish the model coefficients, but the authors' downloadable package does, together with a plain statement of the algorithm and a worked example. The independent implementation reproduces their published output for both example sequences (41.535 percent and 64.448 percent) to three decimal places, so the column is the tool it claims to be rather than an approximation of it. | Delete `pipeline/solubility.py:protein_sol` and drop the column from `pipeline/columns.py` |
| 18 | Aggrescan3D dropped. | Install the standalone or port its scoring | The standalone is Python 2.7 only (the authors state Python 3 is not supported), last released at 1.0.2, and its licence is contradictory: the repository file says MIT while the PyPI metadata says "free for non-commercial users". A non-commercial term is incompatible with spec 7's licence-clean requirement, and an unresolved licence is worse than a missing column. Spec 0.2 names exactly this fallback: SWI and Protein-Sol alone, with the missing term noted on the About tab. | Resolve the licence with the authors, then port the a3v-scale structure-weighted average onto the existing models and FreeSASA |
| 19 | Nativeness uses AbLang2, not nanoBERT. | nanoBERT, which is nanobody-specific and therefore the better-matched prior | nanoBERT is CC-BY-NC-SA-4.0. A non-commercial, share-alike model in a public repo fails spec 7. AbLang2 is BSD-3 and ships a named `pseudo_log_likelihood` mode, so there is no bespoke masking loop to get wrong. The cost is real and is stated on the About tab: AbLang2 is trained on paired human and mouse antibodies, so for a VHH it is a general antibody-nativeness prior rather than a nanobody-specific one. | Swap the model in `pipeline/nativeness.py` if the licence ever permits |
| 20 | Humanness uses `promb` rather than the full BioPhi OASis database. | `biophi oasis` with the 22 GB `OASis_9mers_v1.db` in its own python 3.9 environment | promb is MIT, by the same authors, and computes the same peptide-level OASis identity in memory. BioPhi pins flask<3, sqlalchemy<2, pandas<2.2 and anarci 2020.04.23, so it needs a separate environment that cannot be shared with TNP, plus a 22 GB random-read SQLite. OASis percentiles are calibrated on human antibody repertoires and are not a validated humanness call for a VHH either way, so the column is a descriptor and the heavier route buys nothing. | `conda create` a py3.9 BioPhi environment and point `pipeline/humanness.py` at the full database |
| 21 | The Tm model trains on the NanoMelt paper's CC-BY supplementary dataset (640 curated apparent-Tm nanobodies) with NbThermo as the second source. | NbThermo alone | Spec 6.3 asks for NbThermo plus the published curated apparent-Tm dataset, and this is that dataset. The NanoMelt code is CC-BY-NC-SA and is not used or installed; its training labels are published separately under the article's CC-BY licence, taken from the journal supplementary rather than from the code repository. NbThermo's own repository carries no licence file, so it is cited to its CC-BY paper and only derived values ship. | Train on NbThermo alone in `pipeline/tm_model.py` |
| 22 | TNP installed from its GitHub tag with `--no-deps`, not from bioconda or PyPI. | `conda install -c bioconda tnp`, as the TNP README says | The bioconda package does not exist, and `pip install tnp` fetches an unrelated GCP pipelining package of the same name. The repository's own environment pins python 3.13 and pytorch 2.13, which would need a second environment; every other dependency it needs is already solved here, so `--no-deps` against the tag is the one route that keeps a single environment. | Create a separate `tnp` pixi feature pinned to the repository's `environment.yml` |
